# 今天 App：步骤关联与整组循环需求文档

文档版本：1.0  
日期：2026-09-18  
现有应用基线：0.5.1（Android / Kotlin / Jetpack Compose）  
用途：交给其他开发者或 AI 实现。本次仅编写需求文档，未修改应用代码。

## 1. 需求概述

用户希望将多个步骤关联为一个内部有序的整体。组内第一步进入“下一步”时，整组锁定，当前目标必须依次完成本组全部步骤，才能继续本目标的其他步骤。

**关联只约束当前目标，允许切换到其他目标。循环以整个关联组为单位。**

例如，将 A“准备材料”、B“制作”、C“收拾”关联起来：

```text
同一目标原队列：X、[A → B → C]、Y
执行顺序：X → A → B → C → Y

允许在 A 完成后去执行另一个目标的步骤。
回来继续此目标时，必须接着做 B，不能跳到 C 或 Y。

如果此组设为循环型：
第 1 轮：[A₁ → B₁ → C₁]
第 2 轮：[A₂ → B₂ → C₂]
每轮内部必须完整、有序；不会单独循环 A、B 或 C。
```

## 2. 用户已经确认的要求

1. 能把若干个步骤关联起来，成为内部有序的整体。
2. 首成员进入“下一步”时就锁定，不能等到点击开始或完成首成员后才锁定。
3. 本轮组内成员必须按顺序全部完成，才能继续当前目标的其他步骤。
4. 锁定不影响其他目标，仍可切换到其他目标执行步骤。
5. 保持全应用同时最多一个正在执行的步骤。
6. 关联组需要循环时，以组为单位循环。
7. 本次交付是 Markdown 需求文档，应用实现交由其他 AI 完成。

## 3. 为实现补充的建议约定

下列细节由本需求文档补充，并非用户逐条确认。实现者可将其作为默认方案；如需改变，应说明对行为的影响。

| 事项 | 建议约定 |
| --- | --- |
| 关联范围 | 一个组只属于一个目标，暂不支持跨目标组 |
| 成员数量 | 至少两个步骤；一个具体步骤最多属于一个组，不支持组嵌套 |
| 可选成员 | 只能选尚未进入下一步、执行中或完成状态的待执行步骤 |
| 组执行方式 | 单次关联组、手动结束循环组、累计数值达标循环组 |
| 循环生成时机 | 保持现有习惯：本轮第一步进入下一步时，在本目标待执行队尾预生成下一整轮，且只生成一次 |
| 循环完成计数 | 所有成员完成才计为完成一轮；部分完成不计一轮 |
| 手动结束 | 在本轮最后一个成员完成时，可选择“完成本轮”或“完成本轮并结束循环” |
| 累计型组 | 创建时设置组级目标数值和单位；每轮最后一步完成时填写本轮增量，达标后结束组循环 |
| 中途处理 | 锁定后不允许跳过、拆组、增删成员或强制解锁；允许停留和切换其他目标 |
| 时间要求 | 每个步骤仍必须是一天内可完成的工作；整组不新增一天内完成限制 |

特别说明：用户已确认“以组为单位循环”；上表中的手动结束时机、数值累计填写时机以及副本生成方式，是结合现有功能给出的建议定义。

## 4. 现有功能与兼容边界

应用已有：

- 最多五个未归档目标，新目标截止日期可选今天至 28 天后。
- 每目标最多一个下一步，全应用最多一个正在执行步骤。
- 待执行可以拖动排序，下一步锁定顺序。
- 开始步骤时记录开始时间；完成时记录完成时间；不会自动开始后继步骤。
- 独立步骤支持单次、手动结束循环、累计数值达标循环。
- 独立循环在进入下一步时生成副本，完成次数及数值按历史记录累计。
- 首页显示当前步骤和各目标下一步，详情显示待执行和完成记录。
- 支持统计、本地 JSON、CSV 导入导出。

新增关联不能改变独立步骤的原有循环行为。现有数据升级后保持未关联，不按名称、邻接位置或循环系列自动建立关联。

## 5. 核心概念

| 概念 | 定义 |
| --- | --- |
| 关联组定义 | 组所属目标、名称、成员模板及顺序、单次或循环配置 |
| 组循环系列 | 多轮关联组共同所属的稳定身份，用来累计完成轮数和组级数值 |
| 一轮／组实例 | 本轮需要完整执行的一组成员，如 A₁、B₁、C₁ |
| 成员实例 | 一轮中某个具体步骤，具有独立步骤 ID、状态与执行时间 |
| 成员位置 | 成员在组内的顺序位置；不能通过名称推断 |
| 本目标关联锁 | 指向当前目标尚未完成的已锁定轮次，约束本目标可开始的步骤 |
| 当前应执行成员 | 本轮按顺序最早尚未完成的成员 |

**关联锁属于目标；执行名额属于整个应用。**

允许目标甲和目标乙各有一个已锁定组，但同一时刻仍只能有一个成员正在执行。关联锁在两次执行之间不会消失。

## 6. 建立关联与调整队列

### 6.1 建立关联

在目标详情的待执行区域提供“关联步骤”入口：

1. 多选至少两个符合条件的步骤。
2. 默认按它们在原待执行队列中的相对顺序排列。
3. 展示内部顺序预览，可拖动调整。
4. 选择组执行方式：单次、手动循环、累计达标循环。组名可选，默认以首步骤名称及成员数量展示。
5. 累计型填写组级目标数值和单位，例如“100 页”。
6. 确认后一次性保存，取消不改原数据。

组放到原队列中最靠前的被选成员位置，未选步骤保留彼此的相对顺序。

例如：原队列 `A、X、B、Y、C、Z`，选中 A、B、C 后变成 `[A → B → C]、X、Y、Z`。保存前必须预览此变化。

### 6.2 未锁定时

- 外层拖动移动整轮关联组，不允许把独立步骤拖进组内。
- 组内顺序通过单独的“编辑关联”操作调整，不与外层拖动混用。
- 单次组及尚未产生任何锁定轮次的循环组，允许增减成员、重排或解除关联。
- 移出的成员默认放在组后面，多个移出成员保持相对顺序。
- 待安排组少于两个成员时解除关联，剩余成员作为独立步骤保留。
- 解除关联不删除步骤，在组原位置按原内部顺序展开。
- 未开始的循环组解除关联后，成员作为单次型步骤保留，不把组级循环配置复制成多个独立循环；解除前预览明确提示这一点。
- 删除成员仍受原有步骤删除规则约束，不能通过关联绕过循环副本的保护。

### 6.3 循环系列已经开始后

建议固定成员模板和组内顺序，避免后续轮次出现不同结构或新旧轮次混用。后续整轮在待执行状态时仍可作为整体拖动，但不允许单独删除一个成员、拆散整轮或随意删除未来轮次。

如需改变循环组成员结构，先正常结束该组循环，再新建关联组。文字修正可以提供，但不得改写已经完成的成员内容；同步未来轮次的范围需要在界面明确说明。

### 6.4 已锁定的本轮

- 不允许整轮拖动、成员重排、增删成员、拆组、跳过成员。
- 修改文字沿用现有权限，不改变 ID、归属、顺序和执行数据。
- 仍可创建、查看和整理组外待执行内容，其操作不能改变本轮执行路径。
- 锁定组的成员清单包含已完成成员；不能因为只剩一个未完成成员就自动解散。

## 7. 组内执行与跨目标切换

### 7.1 锁定触发

首成员进入下一步与本目标关联锁建立，必须在同一次状态提交中完成。手动“确认下一项”和自动补位使用相同规则。

如果此时已有无关步骤正在执行，允许它正常完成，不撤回、不重置计时。之后回到这个目标时，必须执行关联组首成员；也允许用户选择其他目标。

每个目标最多有一个已锁定的轮次。其他目标的组可独立锁定，不争抢全局关联锁。

### 7.2 同一目标的推进

以 `[A → B → C]` 后面排有独立步骤 X 为例：

| 操作后 | 正在执行 | 本目标下一步 | 本目标关联锁 |
| --- | --- | --- | --- |
| A 进入下一步 | 无，或此前已经开始的步骤 | A | 锁定本轮 |
| 开始 A | A | B | 保持 |
| 完成 A | 无 | B | 保持 |
| 开始 B | B | C | 保持 |
| 完成 B | 无 | C | 保持 |
| 开始 C | C | 暂空，X 仍待执行 | 保持 |
| 完成 C | 无 | 按队列补位，例如 X | 释放本轮锁 |

规则：

- 完成 A 后只能从此目标开始 B，不能跳到 C、X 或下一轮 A₂。
- 完成成员不会自动开始后继，需要用户点击开始；开始时间使用实际点击时刻。
- 开始最后一个成员时，不提前把组外步骤提升为下一步，以免提前锁定下一组或触发组外循环。
- 最后一个成员完成后，记录整轮完成、释放本轮锁，再正常补位。若队首是新组，就在同一提交中锁定新轮次。
- 开始时的自动补位必须识别组内后继，不能直接取扁平待执行列表的第一项。

### 7.3 允许切换其他目标

例：甲目标的 A 完成，B 是下一步；乙目标的 D 也是下一步。

- 此时允许开始乙目标的 D。
- D 正在执行时，所有其他开始按钮仍受全局单执行名额限制。
- D 完成后，可以回甲执行 B，也可以继续乙目标的合法下一步。
- 甲的关联锁不会因切换、息屏、跨天或重启而解除。
- 不得在首页将“甲目标还有未完成关联组”当作禁用乙目标开始按钮的原因。

跨目标切换以当前正在执行的步骤已经完成为前提；本次功能不新增执行中步骤的暂停、挂起或并行执行能力。

## 8. 整组循环规则

### 8.1 每轮都是完整关联组

假设组 G 的成员为 A、B、C：

```text
G 第 1 轮：[A₁ → B₁ → C₁]
G 第 2 轮：[A₂ → B₂ → C₂]
G 第 3 轮：[A₃ → B₃ → C₃]
```

每轮有独立轮次 ID，每个成员有独立步骤 ID；所有轮次共享组循环系列 ID，成员通过稳定的模板位置对应。

不允许 A 单独生成 A₂ 后脱离组队列，也不允许先做 A₁、A₂，再做 B₁。组内成员完成一次就完成其本轮职责。

### 8.2 预生成下一轮

沿用现有“进入下一步时生成后续”的产品习惯：

1. A₁ 进入下一步时，自动在本目标外层待执行队尾追加完整的第 2 轮 `[A₂ → B₂ → C₂]`。
2. B₁、C₁ 进入下一步时不再生成轮次，也不触发原独立步骤的循环生成。
3. 第 1 轮完成后，如果下一轮之前还有 X、Y，则先按原队列执行 X、Y。
4. A₂ 进入下一步时，再追加完整第 3 轮。
5. 同一组循环系列最多保留一个尚未锁定的未来轮次；不能因重启、恢复备份、重复点击而重复生成。
6. 当前轮尚未完成时，未来轮不能进入下一步，即使用户将它作为整体移到组外队列最前面。

**锁定的是当前轮，不是整个循环系列的所有未来轮次。** 一轮完成后即可按本目标外层队列继续其他内容，循环组不会无限占住本目标。

### 8.3 完成计数

- 只有本轮所有成员均完成，才将组的“已完成轮数”加一。
- A₁、B₁ 完成但 C₁ 未完成时，显示“本轮已完成 2 / 3 步，累计完成 0 轮”。
- C₁ 完成后显示累计完成 1 轮。
- 步骤统计仍按每次成员完成计数；一个三成员组完成一轮，统计为 3 步，组卡片为 1 轮。
- 组本身不额外产生一个完成步骤，不额外重复累计执行时长。

### 8.4 手动结束整组循环

仅在本轮最后一个成员完成时提供：

- “完成本轮”：记录最后成员与本轮完成，保留预生成的下一轮。
- “完成本轮并结束循环”：确认后记录本轮完成，结束组循环系列，移除预生成的未来整轮，保留所有历史成员、时间与轮次。

组内前面的成员仍使用普通完成按钮，不提供“跳过后面的成员并结束组循环”。结束一个组循环不能清理其他组或独立循环步骤的数据。

### 8.5 累计数值达标的整组循环

建议复用现有累计型交互，但数值归属调整为整轮：

- 创建组时填写组级目标数值、单位，例如 100 页。
- 本轮最后一个成员完成时填写本轮完成量，例如 15 页。之前的成员完成不弹出组累计数值输入。
- 确认后同时完成最后成员、完成本轮、累计数值。
- 未达标则继续循环；达到或超过目标时结束组循环并清理未来整轮，保留超额实际数值。
- 取消输入、无效数值或保存失败，不完成最后成员，不计轮数、不累计、不释放本轮锁。
- 使用精确十进制算法，继续沿用大于 0、最多 12 位整数及 6 位小数的数值规则。
- 卡片显示“本轮 2 / 3 步”“已完成 4 轮”“累计 60 / 100 页”等对应信息。
- 本轮数值只记录一次，不能复制到每个成员后再求和，也不能混加不同单位。

## 9. 原有独立循环步骤如何加入组

这是与现有版本衔接的重要边界。建议采用以下规则，并在创建关联预览中明示：

1. 未关联的独立循环保留现有行为。
2. 加入循环组后，成员只执行本轮一次，使用组级循环配置，不再独立生成副本。
3. 尚未启动过的独立循环步骤可以选入组，但确认前必须提示“加入后按整组循环，原单步骤循环设置将不再单独生效”，并明确展示新组模式、目标数值和单位。
4. 已经产生下一步、执行记录或历史完成记录的独立循环，其未来副本暂不允许直接关联。用户需要先正常结束原独立循环，再创建新成员加入组，避免静默改写原循环历史或删除副本。
5. 多个成员各自有不同累计目标和单位时，不能自动合并。由用户明确填写新组的数值配置。
6. 不支持“整组循环 + 组内成员再各自循环”的嵌套循环。不得默默保留两套生成机制。
7. 已确认切换为组成员的步骤保留具体步骤 ID；保存成员归属和停用旧独立循环配置需一次性完成。取消建组应完整保留原设置。

这一部分是建议的迁移约定。如果实现者希望支持直接吸收已开始的独立循环，需要另行设计历史归属及未来副本迁移，不能以删除历史或隐式结束循环解决。

## 10. 页面与交互要求

### 10.1 目标详情

- 未锁定轮次以外层整体卡片展示，可展开成员；外层拖动整组，内层展示内部顺序。
- 显示组名、执行方式、成员数量、当前轮进度和累计轮数，累计型另显示数值进度。
- 已锁定轮次展示“本目标内需按顺序完成”，避免误导用户认为所有目标都被锁。
- 组内剩余待执行成员展示锁定标识，不能作为普通可拖动卡片散落到组外。
- 已完成成员可在本轮进度中回看，但底层完成记录只保存一次。
- 整组结束后保留可查看的组和轮次历史。

### 10.2 首页

- 仍只显示全应用当前步骤及各目标下一步，不把整个待执行组展开到首页。
- 组成员卡片补充组名、当前成员序号、轮次进度，例如“阅读流程 · 本轮第 2 / 3 步”。
- 当前步骤为空时可以继续提示选择下一步，因为跨目标切换仍然允许。
- 甲目标的关联锁不禁用乙目标的合法下一步；全局有正在执行步骤时，其他开始按钮仍禁用。
- 本目标被锁时，任何组外开始入口都应解释：“请先完成本目标的当前关联组，还剩 N 步。”

### 10.3 历史与统计

- 每个成员分别保留开始、完成时间和步骤内容。
- 组历史记录成员模板位置、实际实例、轮次及本轮数值。
- 已完成步骤数量、累计时长按成员统计；轮数与数值是组级统计，不能重复计入步骤汇总。
- 目标归档需要全部成员和未来队列完成或按既有规则结束，不能因组卡片折叠而遗漏未完成内容。

## 11. 持久化、升级与 CSV

关联关系、轮次与本目标关联锁必须持久化，不能仅存在于界面临时状态。

### 11.1 至少需要表达的数据

- 组定义 ID、目标 ID、组名、内部成员模板及顺序。
- 组执行方式，以及组级累计目标、单位、系列结束状态。
- 轮次 ID、所属组系列、稳定轮次顺序、该轮有序成员实例 ID。
- 成员实例的状态、时间、原有内容与历史归属。
- 每目标当前锁定轮次的引用。
- 已完成轮次的完成记录与本轮增量。
- 待执行外层的完整顺序：独立步骤与整轮关联组的位置关系。

具体字段和表结构由实现者决定。可以推导的计数优先从记录计算；若冗余保存，必须验证一致性，不能依赖多个互相冲突的状态来源。

### 11.2 状态校验

- 成员引用存在、归属同一目标、无重复、无嵌套。
- 每个目标最多一个关联锁，但不同目标可以同时有锁。
- 全应用仍最多一个执行中步骤。
- 已完成成员构成本轮有序成员的连续前缀；后继不能越过前驱执行。
- 锁定轮次包含完整成员清单，不因已完成成员移入历史而丢失顺序关系。
- 下一步、当前成员、目标关联锁与未来轮次之间一致，不允许下一轮提前进入执行路径。
- 每个循环系列最多一个未来待安排轮次；组内成员不能带生效的独立循环生成机制。
- 组已完成轮数、本轮进度、累计量、结束状态与原始记录相符。
- 已结束系列无未来轮次；结束不能删除已完成历史。

### 11.3 保存与迁移

1. 当前 JSON 内容版本为 4，CSV 为 v3。扩展时提升相应版本，并兼容旧格式读取。
2. 旧数据按无关联处理，保留独立循环、步骤、顺序、时间及历史数值。
3. 保持旧版 29 天目标兼容，不因本次关联升级改变日期规则。
4. 锁定、生成下一轮、完成成员、完成轮次、数值累计、清理未来轮次和补位，应按实际操作在同一次原子提交中处理。
5. 保存失败不更新界面；重复提交或过期步骤 ID 不重复计数、不重复生成、不跳过成员。
6. 重启、跨日、手机重启后，继续同一轮、同一目标关联锁和原开始时间。

### 11.4 CSV 备份

- 导出包含完整组定义、轮次、成员顺序、外层顺序、各目标锁定信息与轮次数值。
- 执行中途备份再恢复，应回到完全相同的组进度，不能自动解除关联或重新生成下一轮。
- 保留原有导入预览与整份替换流程。用户确认恢复另一快照是显式数据恢复操作，恢复后遵守该快照的关联状态。
- 缺失成员、重复归属、无效轮次、同目标多个关联锁、顺序矛盾、数值不一致的备份应拒绝，不能静默修复为独立步骤。
- 允许不同目标同时各有一个锁；不能误用“全应用只能有一个关联锁”的校验。

## 12. 验收标准

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| A01 | 从 A、X、B、Y、C 选 A/B/C 建组 | 预览并保存为 [A→B→C]、X、Y，其他步骤相对顺序不变 |
| A02 | 拖动未锁定组 | 整体移动，不拆散成员 |
| A03 | 编辑未锁定结构、解除关联或取消建组 | 按约定调整；取消无变化，解除关系不删除步骤 |
| A04 | A 进入下一步但尚未开始 | 立即锁定本轮，不能开始本目标组外步骤 |
| A05 | A 完成，B 尚未开始 | 本目标关联锁保持，可开始另一目标步骤 |
| A06 | 两目标各有锁定组 | 允许存在，仍只有一个正在执行步骤；切回来继续各自正确成员 |
| A07 | A/B/C 依次执行 | 顺序不可跳过，各自计时，不自动开始后继 |
| A08 | C 开始但未完成 | 本目标组外步骤和下一轮均不提前进入下一步 |
| A09 | C 完成 | 正确记录本轮、释放本目标旧锁并补位，不改变其他目标的锁 |
| A10 | 已锁定后尝试拖动、拆组、跳过或删除成员 | 所有入口拒绝，业务层也拒绝 |
| A11 | 本轮首成员进入下一步 | 只追加一次完整下一轮，每个成员使用新实例 ID |
| A12 | 本轮第二、第三成员进入下一步 | 不生成新的整轮，也不生成独立成员副本 |
| A13 | 当前轮未完成，把未来轮拖到外层队首 | 仍不能提前开始未来轮，不影响当前轮内部顺序 |
| A14 | 当前轮与未来轮之间排有独立步骤 X | 完成本轮后可以按队列执行 X，不强制连续做所有未来轮 |
| A15 | 三成员组只完成两步 | 统计完成 2 步，组完成 0 轮 |
| A16 | 三成员组完成一轮 | 统计完成 3 步、组完成 1 轮，无额外第四步或重复时长 |
| A17 | 最后成员选择完成并结束组循环 | 计入本轮，移除未来整轮，保留历史和其他队列项 |
| A18 | 累计组本轮输入 15，原累计 20，目标 100 | 变为 35，完成一轮并继续循环 |
| A19 | 本轮累计达到或超过目标 | 完成本轮后结束组循环，保留超额量，移除未来整轮 |
| A20 | 累计弹窗取消、输入无效或保存失败 | 最后成员仍执行中，不计轮数、不累计、不释放锁 |
| A21 | 将未启动的独立循环选入组 | 预览明确切换为组级循环，保存后不保留双重生成机制；取消不改原设置 |
| A22 | 将已有历史的独立循环副本选入组 | 按第 9 节拒绝并说明原因，不修改旧历史 |
| A23 | 中途重启、跨日、退出后返回 | 每目标锁、成员、轮次和开始时间不变 |
| A24 | 导出并恢复两个目标各有锁的 CSV | 完整恢复，允许两个目标锁，仍保持全局单执行名额 |
| A25 | 读取旧版 JSON/CSV，包括旧 29 天目标 | 保持原独立步骤与循环，不丢记录，不自动关联 |
| A26 | 重复点击、过期请求、保存失败 | 无重复轮次、重复累计、部分解锁或步骤丢失 |
| A27 | 导入损坏的组关系或轮次 | 明确拒绝，不覆盖原数据 |

验证结果应区分编译通过、业务测试通过、设备交互测试通过与实际截图检查，不能把仅编译的设备测试记为真机已通过。
