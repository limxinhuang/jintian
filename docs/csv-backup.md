# CSV 备份格式 v3

应用版本：今天 0.5.0 起。一个 CSV 文件可以恢复一份完整应用快照。v3 为 24 列，每条记录版本均为 3，不允许混用版本。导入仍支持 v1（18 列，单次型）和 v2（21 列，单次型／手动循环）备份。

## 读写约定

- UTF-8 编码，导出带 BOM，导入接受带或不带 BOM。
- 逗号分隔。导出使用 CRLF 行结束符；导入也接受 LF。
- 导出所有字段使用双引号包围，内部双引号写成两个双引号，字段内换行保留。
- 日期使用 `yyyy-MM-dd`；时间使用带 UTC 时区的 ISO 8601，例如 `2026-09-17T02:30:00.123Z`，毫秒精度保留。
- 文件最多 10 MB、50,000 条记录（含表头和备份信息）。
- 应保留应用导出的原始备份用于恢复。表格软件另存 CSV 时可能改变日期、ID 或时间格式。

## 列

列名与顺序固定：

| 列 | 含义 |
| --- | --- |
| 格式版本 | 当前为 3，每条记录均填写 |
| 记录类型 | 备份、目标、步骤 |
| 目标ID | 目标唯一 ID，步骤通过它关联目标 |
| 目标顺序 | 从 1 开始的连续目标顺序 |
| 目标名称 | 原始名称 |
| 开始日期 | 目标创建当天的本地日期 |
| 截止日期 | 目标截止日期 |
| 已归档 | 是或否 |
| 目标创建时间 | 创建时刻；旧数据可为空 |
| 步骤ID | 步骤唯一 ID |
| 步骤顺序 | 在同一目标、同一状态内从 1 开始的连续顺序 |
| 步骤内容 | 原始步骤文字 |
| 步骤状态 | 待执行、下一个、正在执行、已完成 |
| 步骤开始时间 | 正在执行和有完整时间记录的已完成步骤填写 |
| 步骤完成时间 | 已完成步骤填写；旧版无时间记录的步骤可以两列均为空 |
| 导出时间 | 备份生成时间 |
| 目标总数 | 包含空目标、已归档目标 |
| 步骤总数 | 包含四种状态的全部步骤 |
| 步骤类型 | 步骤记录填写单次型或循环型 |
| 循环ID | 循环型填写稳定的系列 ID，单次型留空；与步骤 ID 不同 |
| 循环已结束 | 步骤记录填写是或否，单次型必须为否 |
| 累计目标数值 | 仅累计型循环填写正数，普通循环与单次型留空 |
| 累计单位 | 累计型填写，如页、公里；同一循环单位固定 |
| 本次完成数值 | 仅累计型已完成记录填写本次增量，其余记录留空 |

## 记录类型

文件第一行为表头，之后必须有且仅有一条「备份」记录，填写导出时间与目标／步骤总数。数量用于发现被截断或丢失记录的文件。

每个目标有一条「目标」记录，填写目标字段；每个步骤有一条「步骤」记录，填写目标 ID、步骤字段。即使没有步骤，目标仍有独立记录。空应用导出表头及零计数的备份记录。

每种记录未使用的列保持为空。导入允许物理行顺序改变，目标和步骤的顺序以相应顺序列为准，不以文件中的行位置为准。

为让以 `= + - @` 等字符开头的文本在表格软件中按文字显示，导出会添加可逆的单引号前缀；原本以单引号开头的文字也会转义。应用导入时还原原始文字，不对文字执行公式。

## 恢复规则

先完成全文件解析与校验，再生成预览。校验包括唯一 ID、目标引用、连续顺序、数量一致、时间字段及应用状态约束。未知版本、缺列、多列、未闭合引号、非 UTF-8、无效日期和状态均会拒绝。

确认恢复采用完整替换；写入经过原有数据仓库和 AtomicFile。预览后如发生其他修改则拒绝旧预览，保存失败不发布新状态。当前执行中的步骤使用原开始时间继续累计。CSV 不单独保存统计汇总，避免汇总与原始记录不一致。

循环完成次数从同一循环 ID 的已完成记录数量计算，不另存计数列。循环不能跨目标，结束状态必须一致；结束后的循环只能有历史记录，进行中的循环必须有且仅有一个待执行副本。恢复不追加副本，已结束的循环不会重新开始。没有结束的循环允许同时存在当前执行、下一项及一个待执行副本。

累计数值从同系列完成记录的本次增量求和，不另存总量。使用十进制字符串精确还原，同系列目标数值和单位必须一致；累计达到或超过目标时必须已结束，未达标时不能标为结束。数值只接受大于 0 的十进制数，最多 12 位整数与 6 位小数，不接受科学计数法、负数或非数值。缺失完成量、非累计型带数值、未完成步骤带增量以及累计值与结束状态冲突的备份均拒绝恢复。

Android 文件访问使用 [Storage Access Framework](https://developer.android.com/training/data-storage/shared/documents-files) 的创建和打开文档操作，由用户选择文件及位置。
