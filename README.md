# 今天 · 安卓目标应用

原生 Kotlin / Jetpack Compose 应用。当前版本 0.5.1，支持 Android 8.0 及以上。

## 功能

- 同时最多五个目标，创建时只填写名称和截止日期；开始时间自动记录，截止日期可选今天至四周后（0～28 天），没有至少一周的限制。
- 日历顶部高对比显示今天的日期，当天格子加粗、描边并标注「今天」，与所选截止日分别标识；支持一键选择今天，范围外日期不可选。
- 每个目标拆成多个一天内必须完成的步骤。添加时选择单次型或循环型、填写内容，不填写预计时长，不需要勾选确认。
- 单次型完成一次即结束；循环型每次进入下一项时自动在待执行队尾追加一次，各卡片显示该循环已完成次数。
- 循环支持手动结束或累计数值达标结束；累计型创建时填写目标数值和单位，完成时填写本次增量，达到或超过目标后自动结束。
- 待执行步骤按添加顺序排列，可长按整张卡片拖动排序；拖到列表边缘会滚动。没有上下箭头。
- 排序后确认第一项，成为锁定的「下一个」。只能修正文字，不能删除或改变顺序。
- 全应用同时只有一个正在执行的步骤。开始时，待执行队首自动补位为下一项；完成后由用户选择接下来做什么。
- 当前步骤显示开始时间和已持续时间，退到后台、关闭应用、重启手机后继续按原开始时间计算。
- 一天倒计时显示今天剩余时间和已过去的比例，每秒更新，到本地午夜重置。不会自动完成跨日步骤。
- 底部「今天 / 统计」导航。统计包含今日完成、累计完成、已完成目标、累计执行时长、近七天完成情况、目标进度与最近完成记录。
- 完成的目标可归档，不占五个名额；归档记录仍计入统计。刚创建的空目标可删除。
- 数据保存到手机本地，支持浅色和深色；无需账号或网络权限。
- 在「统计 → 数据备份」导出 CSV，或导入之前导出的 CSV 恢复完整数据；通过系统文件选择器选择文件和保存位置，无需存储权限。

## CSV 备份

导出包含所有目标（含空目标与已归档目标）、步骤、顺序、执行状态、目标创建时间及步骤开始／完成时间。UTF-8 编码并带 BOM，可以在 Excel、WPS 等表格软件中查看。

0.5.0 导出格式 v3，保存步骤类型、循环 ID、结束状态、累计目标、单位和每次完成量，完成次数和累计值从记录恢复；仍可导入 v1、v2 备份，旧步骤保持原来的类型与循环方式。

导入先校验，再显示备份日期、目标和步骤数量及恢复预览。点击「替换并恢复」后整份替换当前数据，不进行合并。恢复前如需保留当前记录，请先导出当前数据。空备份会明确提示将清空当前记录。

无效文件、取消选择或取消预览不会修改数据。导入还会遵守最多五个未归档目标、全应用最多一个执行中步骤、每目标最多一个下一项等规则。预览后如果当前数据发生变化，需要重新选择文件，避免覆盖新修改；保存失败保留原数据。

恢复执行中步骤时保留原始开始时间，经过时长包含备份期间流逝的时间。统计由恢复的步骤与时间记录重新计算。文件格式说明见 [CSV 备份格式](docs/csv-backup.md)。

## 循环步骤

循环步骤在手动确认下一项、或开始其他步骤时自动补位为下一项，都会生成一个独立 ID 的同系列待执行副本，放在队尾；副本仍可拖动排序。进入下一项后顺序保持锁定，重启或恢复备份不会额外生成副本。

手动结束的循环在执行时可选「完成本次」继续循环，或「完成并结束循环」。后者先确认，计入本次完成次数，移除同一循环预生成的下一项和待执行副本，保留所有完成记录及开始／完成时间，其他步骤不变。若移除了下一项且仍有其他待执行步骤，可在详情确认新的下一项。

累计型循环：创建步骤时选「循环型 → 累计数值达标」，填写目标数值及单位，如 100 页。每次点击完成后填写本次数值，如 15 页；确认前显示计入后的累计值。达到或超过目标后自动结束、移除同系列后续项，保留实际完成量（不截断超额量）。卡片显示累计值／目标、进度条和完成次数，历史记录还显示本次完成量。取消或输入无效数值不会完成步骤。目标与单位创建后固定，编辑仅改文字。

数值要求大于 0，最多 12 位整数、6 位小数；单位为 1～12 个字。使用精确十进制计算，例如 0.1 + 0.2 会准确达到 0.3，不受浮点误差影响。

未开始的循环可以删除；已经进入流程的循环副本不能单独删除，手动循环请在执行时结束，累计型在达标时结束。编辑循环文字会同步到同系列的待执行和下一项，当前执行内容与历史记录不变。不同循环即使同名也分别计数。统计按每次完成计为一步，不跨不同单位相加；开放循环的后续数量会继续增长。

## 时间规则

「一天内完成」是步骤拆分的固定要求，不是用户可选设置。软件不会凭步骤文字判断工作量。步骤开始超过 24 小时会提示超时，仍保留执行记录，不会伪造完成状态。

执行时长是开始到现在／完成时刻的实际经过时间，包含后台、息屏和应用关闭的时间，不等同于有效工作时长。系统时间被手动调早时，负时长按零显示。

一天进度按设备当前时区的本地午夜边界计算，支持跨日、时区变化和夏令时。最近七天的完成日期按设备当前时区归组。累计执行时长包含正在执行的步骤。

## 构建

需要 JDK 17、Android SDK Platform 35 和 Build Tools 35.0.0。项目包含 Gradle 8.11.1 Wrapper。

1. 在 Android Studio 中打开项目，或配置 `JAVA_HOME` 指向 JDK 17。
2. 在不提交的 `local.properties` 写入本机 `sdk.dir`。
3. 执行：

```powershell
.\gradlew.bat :app:testDebugUnitTest :app:assembleDebug :app:lintDebug
```

开发安装包：`app/build/outputs/apk/debug/app-debug.apk`。
交付副本：`artifacts/jintian-0.5.1-debug.apk`。

AGP / SDK / JDK 的版本配合参考 [Android 官方兼容说明](https://developer.android.com/build/releases/agp-8-9-0-release-notes)。

## 项目结构

- `domain/`：不可变数据、状态推进、当天时间计算和统计计算。
- `data/`：带版本的 JSON、AtomicFile 保存、串行读改写、CSV 编解码与系统文件读写。
- `ui/`：首页、详情、简化表单、卡片拖动、底部导航和统计。
- `src/test/`：本地逻辑与持久化测试。
- `src/androidTest/`：设备端操作和文件测试；使用独立测试数据，不写入用户的目标文件。

应用包名为 `com.jintian.app`。本地数据存于应用私有目录的 `goals-v1.json`，文件名保持兼容，内容版本为 4，支持读取版本 1、2、3。版本 1、2 的步骤默认单次型，版本 3 的循环保持手动结束。旧版已完成步骤没有真实开始／完成时间时，只计入累计数量，不虚构日期或耗时。写入成功后才更新界面，读取失败不会用空数据覆盖原文件。

0.5.1 创建新目标限制为 0～28 天；为兼容旧版，已存在及备份中的 29 天目标可正常读取、编辑和恢复，不改变原截止日。
